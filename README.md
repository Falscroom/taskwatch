# taskwatch

Монитор MR из GitLab и тасок YouTrack в строке меню macOS: карточки «что требует
твоего действия» и одноразовые уведомления о новых событиях. Go + Wails v3.

Это README для разработчика. Инструкция для коллег (установка из архива) —
[packaging/README.md](packaging/README.md).

## Сборка и проверка

Нужны Go 1.26+, Xcode Command Line Tools, golangci-lint v2 (для `make lint`) и node
(для тестов фронтенда; без него они пропускаются).

```bash
make build    # bin/taskwatch
make app      # bin/taskwatch.app — бинарь + Info.plist + иконка, подпись ad-hoc
make icon     # пересобрать packaging/taskwatch.icns из генератора packaging/icon
make check    # vet + lint + test + тесты фронтенда — должно быть зелёным перед коммитом
make demo     # окно в браузере на поддельных GitLab/YouTrack: http://127.0.0.1:7778
make demo-app # то же демо в меню-баре, в настоящем окне Wails
make dist     # dist/taskwatch-mac.zip для раздачи
make install  # поставить себе taskwatch.app как LaunchAgent
```

Тесты не трогают настоящую Связку ключей и не шлют настоящих уведомлений: вместо них
`testutil/fakesecrets` и заглушка Notifier, вместо GitLab и YouTrack — `testutil/fakeapi`
на httptest. Единственное исключение — тест самой Связки ключей, он включается явно:
`TASKWATCH_KEYCHAIN_TEST=1 go test ./internal/platform/keychain`.

## Режимы запуска

```
taskwatch [-config path] [-addr host:port] <command>
  app           иконка в меню-баре + уведомления (по умолчанию)
  web           то же окно в браузере на -addr (127.0.0.1:7777) — для отладки
  run           цикл опроса и уведомления без UI
  once          один проход опроса
  status        таблица тасок, MR, апрувов и сборок
  secret-clear  удалить токены из Связки ключей (зовёт uninstall.sh)
```

`app` и `web` стартуют и с неполным конфигом — окно попросит недостающее; остальным
командам нужен валидный. Режим `web` отвечает только на loopback-адреса и отклоняет
запросы с чужим Origin.

Где что лежит:

| Что | Где |
|---|---|
| Настройки (без токенов, права 0600) | `~/.config/taskwatch/config.yaml`, пример — [config.example.yaml](config.example.yaml) |
| Токены | Связка ключей, сервис `com.taskwatch`, аккаунты `gitlab` и `youtrack` |
| Токены в обход Связки ключей | `TASKWATCH_GITLAB_TOKEN`, `TASKWATCH_YOUTRACK_TOKEN` — env главнее |
| Отправленные уведомления, заглушения, счётчики прошлого опроса | `state.json` рядом с конфигом |
| Установленное приложение | `~/.local/share/taskwatch/taskwatch.app`, команда `~/.local/bin/taskwatch` — ссылка на его бинарь |
| Лог LaunchAgent'а | `~/.config/taskwatch/taskwatch.log` |

Для ручных прогонов на своём конфиге задавай **оба** env-токена: тогда Связка ключей
не читается вовсе. Окно без настоящих аккаунтов — `make demo` (браузер) или
`make demo-app` (меню-бар): они ничего не трогают ни в Связке ключей, ни в `~/.config`,
а уведомления пишут в лог.

## Как это устроено

### Один проход опроса

`engine.Run` делает проход раз в `poll_interval` и по кнопке «Обновить»:

```
 GitLab ───┐
           ├──▶ collect ──▶ glitchGuard ──▶ снапшот ──▶ alerts.Evaluate ──▶ Dispatcher
 YouTrack ─┘   (порты)     (не пустота ли?)    │                                │
                                               │             уведомление macOS ◀┤
                                               │            авто-перевод таски ◀┤
                                               │           state.json: «слали» ◀┘
                                               ▼
                                          publish: версия + 1
                                               ├──▶ подписчики: цифра на иконке
                                               └──▶ long-poll GET /api/view ──▶ view.Build ──▶ окно
```

1. **collect** берёт таски и MR через порты `TaskSource` / `MRSource` и параллельно
   догружает детали (апрувы, ревьюеры, сборки, комментарии). Ему всё равно, откуда
   данные: адаптеры — `integrations/gitlab/source.go` и `integrations/youtrack/source.go`.
2. **glitchGuard** не верит внезапной пустоте: GitLab иногда отдаёт пустой список без
   ошибки. Такой снапшот принимается только со второго раза, а до тех пор на экране
   остаётся прошлый.
3. **alerts.Evaluate** превращает снапшот в события. У каждого — стабильный ключ
   (`pipeline:<id>:<status>`, `review:<mr id>` …), и **Dispatcher** доставляет событие
   ровно один раз: заглушённое — помечает и молчит, уже отправленное — пропускает,
   на первом запуске — только помечает (чтобы не завалить старым), остальное —
   переводит таску (если включён авто-перевод) и показывает. Неудачная доставка
   не помечается и повторится в следующий проход.

   Показывает `tray.Notifier`. Внутри `taskwatch.app` — через Центр уведомлений
   macOS: своя иконка, заголовок «что случилось», подзаголовок «таска · название»,
   клик открывает MR или таску, кнопки «Заглушить на час» и «→ статус», стопка на
   каждый MR, звук только у событий, которые ждут действия (`Kind.Loud`). Вне
   бандла (`run`, `once`, `web`, демо) Центр уведомлений недоступен, и уведомления
   идут запасным путём — `platform/macnotify` (terminal-notifier или osascript).
4. **publish** поднимает версию и будит подписчиков: трей пересчитывает цифру,
   ожидающий long-poll отдаёт окну новый вид. Окно не опрашивает сервер по таймеру.

Все решения «требует работы», «пора переводить», «ждёт твоего ревью» принимает
`domain.Policy` — одна на окно и уведомления.

### Зависимости пакетов

Слои сверху вниз; пакет импортирует только пакеты своего слоя или ниже:

```
 cmd/taskwatch · cmd/taskwatch-demo           склейка: флаги, таблица команд, выбор платформы
 ──────────────────────────────────────────────────────────────────────────────
 ui/tray ─▶ ui/httpapi ─▶ view                окно, HTTP API, иконка в меню-баре
 ui/frontend (HTML/CSS/JS, embed)
 ──────────────────────────────────────────────────────────────────────────────
 app ─▶ collect, integrations/*, engine       сборка зависимостей движка из конфига
 ──────────────────────────────────────────────────────────────────────────────
 engine ─▶ alerts, state, config              цикл опроса; не знает ни GitLab, ни UI
 settings ─▶ config, integrations/*           токены, сохранение формы, проверка связи
 ──────────────────────────────────────────────────────────────────────────────
 collect · alerts · view                      логика над моделью: только domain
 config · state                               файлы: domain + fsutil
 integrations/gitlab, youtrack ─▶ httpx       клиенты API и адаптеры к портам collect
 ──────────────────────────────────────────────────────────────────────────────
 domain                                       модель и правила; не импортирует ничего
 platform/{keychain, macnotify, fsutil}       macOS и файлы
 integrations/httpx                           общий HTTP: JSON, ошибки, повторы
```

На чём держится порядок:

- `domain` ничего не импортирует. Интеграции переводят в него свои форматы, все
  остальные работают с ним.
- `collect` не знает про GitLab и YouTrack — только порты. Новый источник не трогает сборщик.
- `engine` получает клиентов через `Factory` (её реализует `app.Deps`), а UI узнаёт
  о новостях через `Subscribe` и `Version`/`WaitUpdate`. Поэтому движок тестируется на
  поддельном API без окна.
- Клиентов для опроса создаёт только `app`; `settings` создаёт их лишь для кнопок
  «Проверить» и «Подобрать» (доски YouTrack для запроса тасок).
- macOS (`keychain`, `macnotify`) подключается только в `cmd/taskwatch`. Тесты и демо
  подставляют `fakesecrets` и запись в лог.
- Центр уведомлений работает только из бандла с идентификатором (`com.taskwatch`
  в `packaging/Info.plist`). Без бандла его запуск роняет приложение Wails, поэтому
  `tray.Notifier` запускает его сам и при ошибке остаётся на запасном пути.
- `testutil/*` импортируют только тесты и `cmd/taskwatch-demo`.

### Паттерны

| Паттерн | Где | Зачем |
|---|---|---|
| Порты и адаптеры | `collect.TaskSource`/`MRSource` ← `integrations/*/source.go` | сборщик не зависит от API, тестируется без сети |
| Фабрика | `engine.Factory`, реализация — `app.Deps` | смена настроек пересобирает клиентов целиком в одном месте |
| Политика | `domain.Policy` | бизнес-правила в одном месте для окна и уведомлений |
| Наблюдатель | `engine.Subscribe`, `Version`/`WaitUpdate` | трей и окно обновляются по событию, без таймеров |
| Декоратор | `settings.WithEnv(keychain.Store{})` | env-токены главнее Связки ключей без ветвлений в `settings` |
| Неизменяемый снимок конфига | `engine.current` (`atomic.Pointer`) | `Reload` и проход опроса не мешают друг другу без блокировок |
| Таблица команд | `cmd/taskwatch/commands.go` | справка, выбор режима и нужный конфиг — из одного списка |
| Таблица полей | `FIELDS` в `js/form.js` | форма заполняется и читается по одному описанию |
| Делегирование событий | `data-action` + `js/actions.js` | один обработчик кликов на всё окно |
| Атомарная запись | `platform/fsutil.WriteFileAtomic` | `config.yaml` и `state.json` не бьются при падении |
| Запасной путь | `tray.Notifier` → `platform/macnotify` | уведомления работают и без бандла, приложение не падает |

### Окно

`internal/ui/frontend` — без сборщика и зависимостей: `index.html`, `app.css` и ES-модули
в `js/`, встроенные в бинарь через `embed`. Одни и те же файлы и API обслуживают окно
в меню-баре (asset handler Wails) и режим `web`.

- Чистые модули без DOM: `format.js` (даты, сроки, экранирование), `cards.js` (вид →
  HTML карточек, группы, вкладки), `form.js` (форма настроек). Их тесты — `test/`,
  запускает `make test-frontend`.
- Модули со страницей: `api`, `dom`, `store`, `view` (отрисовка и long-poll),
  `mute`, `settings`, `actions`, точка входа `main`.
- Все клики идут через один обработчик: элемент помечен `data-action="имя"`, а
  `actions.js` знает, что это имя делает.
- Модули помечены `// @ts-check` с JSDoc-типами — редактор проверяет их как TypeScript.
- Проверки формы живут на сервере; окно только показывает его ответ.
- Пока окно в меню-баре скрыто, WebKit через несколько секунд приостанавливает его
  JavaScript, и long-poll замирает. Это нормально: при показе окна цикл продолжается
  и сразу получает свежий вид, потому что версия движка за это время ушла вперёд.
  Цифра на иконке от окна не зависит — её обновляет Go через `Subscribe`.

## Куда что добавлять

| Задача | Что менять |
|---|---|
| Новое условие «требует работы» / «пора переводить» | `domain.Policy` и её тест; окно и уведомления подхватят сами |
| Новое уведомление | `alerts/evaluate.go`: событие со стабильным `Key`. Формат ключа не меняется задним числом — по нему `state.json` помнит отправленное |
| Новый источник тасок или MR | реализовать `collect.TaskSource`/`MRSource` в `integrations/<имя>/source.go`, подключить в `app.Deps` |
| Новая настройка | поле в `config` (и в `Policy()`, если это правило); форма в `ui/httpapi/config.go` (`rulesForm`, `formOf`, `config`); строка в `FIELDS` и `<input>` в `index.html`; строка в `config.example.yaml` |
| Новое действие в окне | тонкий хендлер в `ui/httpapi/api.go`, функция в карте `actions.js`, `data-action` на элементе |
| Новая команда CLI | строка в таблице `commands` в `cmd/taskwatch/commands.go` |

Формат ключей заглушений (`mr:<id>`, `title:<название>`) и событий хранится в
`state.json` у пользователей — менять его можно только с миграцией.

## Раскладка

```
cmd/taskwatch/       точка входа и таблица команд CLI
cmd/taskwatch-demo/  демо окна на поддельных данных (make demo)
internal/            весь код приложения
  domain/            модель и бизнес-правила (Policy, MuteRules); ничего не импортирует
  collect/           сбор снапшота через порты TaskSource/MRSource, параллельная догрузка
  alerts/            события из снапшота и их доставка (Dispatcher: один раз, заглушения, авто-перевод)
  view/              карточки окна
  engine/            цикл опроса, защита от пустых ответов, последний снапшот, подписки
  app/               сборка зависимостей из конфига — единственное место, где создаются клиенты
  config/            структура настроек и yaml, без побочных эффектов
  settings/          загрузка конфига с токенами, сохранение формы, проверка связи
  state/             state.json: отправленные уведомления, заглушения, счётчики
  integrations/      GitLab и YouTrack: клиенты поверх общего httpx и адаптеры для collect
  platform/          macOS: Связка ключей, уведомления без бандла; атомарная запись файлов
  ui/httpapi/        HTTP API окна (тонкие хендлеры, long-poll /api/view) и сервер режима web
  ui/tray/           меню-бар на Wails: иконка, окно, цифра «нужно тебе», уведомления
                     Центра уведомлений с кнопками
  ui/frontend/       окно: HTML/CSS и ES-модули в js/, тесты чистых модулей в test/
  testutil/          поддельные GitLab/YouTrack и хранилище секретов для тестов
packaging/           install.sh, uninstall.sh, plist LaunchAgent, Info.plist и иконка
                     taskwatch.app (генератор — icon/), README для коллег
```
